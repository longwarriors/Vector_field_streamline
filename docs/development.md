# 开发指南

## v0.3.9 数学场与材料界面验证边界

本版验收场景为 Laplace 鞍点、三阶多极、线性斜率场、Logistic 斜率场与理想磁屏蔽筒。前四个使用无量纲坐标，最后一个使用 m 与 T；所有预设都必须通过同一套网格、双端终止、手动种子、覆盖播种预算与固定场景校验。

`tests/test_planar_fields.py` 验证谐势梯度、无散无旋、旋转与尺度、解析解曲线不变量、水平斜率不等于零场，以及 callable 广播和非有限值政策。`tests/test_shield_fields.py` 用独立求解的边界条件线性系统对照分段场，检查屏蔽因子、法向 B/切向 H 连续、均匀材料/薄壁/高磁导率极限、平移旋转与二维通量函数；DOP853 和 Radau 的双向轨迹需穿过两侧的四个材料交点，保留折点并满足通量不变量。

Web 验收需覆盖五个预设的真实 API、无量纲坐标、环形材料区域、内腔与壁内手动种子、零场种子的统计，以及前后端对畸形单位和材料字段的拒绝。浏览器的网格预览会在材料界面附近插值，不能用它替代解析边界条件或服务端界面追踪的精度验证。原有静态资源 `Cache-Control: no-cache`（含 304 响应）回归继续保留。

这些检查只验证已声明的二维解析模型和数值轨迹，不证明有限长坡莫合金筒的真实屏蔽性能，也不验证有限端部、开口、多层、非线性、磁滞、涡流或任意 Laplace 边值求解。全套质量门禁和构件验证的实际结果以本次验收记录为准；跨平台与 Python 版本边界仍由 CI 矩阵单独验证。

开发复审发现，屏蔽筒内圆种子 `(0.4949747468305833, 0.4949747468305833)` m 的反向轨迹，在穿过左侧外圆时被误报为沿界面滑行。原计数器只读取每次界面事件前最后一个限步段的行程，忽略了前一次界面重启后已经正常走过的距离。修复改为按两次界面重启之间的累计弧长判定，保留原阈值和真正滑移的停止保护。磁筒案例与独立匀强场穿两圆案例均先确认修复前因 `solver_failure` 失败，再验证修复后正常出域；相关追踪测试共 120 项通过。另检查内外表面 16 个方向的种子，双端均正常出域，最大通量漂移为 $6.843\times10^{-14}$ T·m。

`SlopeField` 的复数 callable 输出曾在浮点转换时静默丢失虚部；新回归先确认该行为，再改为显式拒绝复数。合法实数 callable 的广播与非有限值政策不变。

在最终界面修复后，以发布提交 `a0354480a55d764d8aeb31930601623d51122abf` 为基线，对 17 个旧预设使用 `density=18`、`resolution=32` 比较完整 JSON 响应（省略值为 `None` 的可选字段，与 HTTP 输出一致）；网格、曲线浮点坐标、终止统计和元数据全部一致。这是固定参数下的抽样对照，不是所有输入的逐位一致性证明。真实 Chromium 页面另检查了屏蔽筒与 Logistic 场景的单位、材料双圆、平衡解和画面布局。

## v0.3.8 磁静态验证边界

六个新预设使用固定几何和覆盖播种，不修改原有场景的追踪设置。`tests/test_wire_field.py` 检查右手定则、反比衰减、平行导线叠加、任意公共方向、批量求值和几何奇点；`tests/test_magnetic_scenes.py` 检查轴线解析场、Helmholtz 中心平坦性、反 Helmholtz 梯度、沿场线的通量不变量、种子预算、遮罩、手动零场种子与 API 契约。浏览器关键流程连接真实 API，遍历六个新场景、预览与手动播种。

开发中确认并保留了以下回归证据：

- 极大但有限的坐标会令直导线叉积判据中的绝对值求和溢出，把有限场误判为 `NaN`；新回归先在修复前失败，再将舍入系数乘法移到求和前，恢复有限结果。
- 反 Helmholtz 场景的近导线种子 `(0.918, -0.5)` m 对应约 0.57547 m 的闭环。继承旧圆环预设的 0.6 m 最短闭合弧长时会绕两周，约 1.15092 m；仅将新场景的下限设为 0.2 m 后正确结束一周，回归保留旧设置对照。
- 螺线管首次全套验证在 `density=40` 时失败：回流播种段上界 0.805 m 让最外种子撞入端部导线排除区。将该上界改为 0.790 m，为闭合回路与排除区保留裕量；保留最大预算的回归要求。

这些检查验证理想场和数值轨迹，不覆盖真实螺旋引线、有限导线截面、磁芯或含时电磁效应。低分辨率网格可能没有采到小排除区域；服务端轨迹仍直接使用排除几何，浏览器预览继续遵守网格近似的既有说明。

本项目的完成标准不是“前端能画出曲线”，而是物理、数值、API 和文档均有可重复验证。新功能应从公共契约和可验证基准开始设计。

## 开发环境

```powershell
uv sync
uv run playwright install chromium
```

uv 在项目内维护 `.venv`，`uv.lock` 则固定直接与传递依赖。不要手工修改 `.venv`，也不要在项目工作流中混用 conda 或直接 `pip install`。依赖变更应先改 `pyproject.toml`，再由 uv 更新锁文件。

`.python-version` 固定日常开发使用 Python 3.13；需要验证其他受支持版本时，应在独立 CI 作业中显式选择解释器，不要改动共享虚拟环境。

确认包来自 `src` 布局，而不是仓库根目录的同名文件：

```powershell
uv run python -c "import vectorviz; print(vectorviz.__file__)"
```

路径应指向安装环境映射到的 `src/vectorviz`。

## 测试策略 { #testing-strategy }

先选择能验证本次风险的最小测试集合，开发中只运行受影响的测试，例如 `uv run pytest tests/test_tracing.py --no-cov`。修缺陷时先保留能触发原故障的输入与断言，确认它在修复前失败、修复后通过；失败应来自目标行为，而不是导入或环境错误。积分、播种、奇点处理和 API 契约变更应保留重要失败场景的回归测试。提交前再按质量门禁顺序完整验证，报告实际命令、结果和未验证范围。

### 单元测试

目标是小而确定的数学与数据契约：

- `Domain` 的形状检查、包含判断和维数错误；
- 每个场的单点与批量求值形状；
- 浮点 dtype、有限值政策与奇点行为；
- `CompositeField` 的叠加和维数拒绝；
- 追踪选项校验和枚举序列化。

### 数值验证测试

验证“结果在容差内正确”，而不是只验证代码能运行：

- 匀强场得到平行直线；
- 点电荷方向径向且幅值满足 $r^{-2}$；
- 磁偶极子满足轴线、赤道和 $r^{-3}$ 基准；
- 人工旋转场形成闭环；
- 减小积分容差或最大步长时，轨迹按预期收敛；
- 场线切向与局部场的叉积残差足够小。

建议为误差较敏感的测试记录容差选择依据。不要把容差放宽到足以掩盖算法退化。

预期值应来自独立的解析解、守恒量或已验证收敛的数值求积。让被测函数调用自身生成预期值，或只比较同一公式的两个包装接口，无法证明物理正确性。单点与批量路径的一致性仍需检查，但它验证的是实现路径一致，而不是公式本身。

对每个数值回归保留最小可重现输入：模型参数、单位、种子、区域、排除几何、积分选项和断言依据。记录实际残差与容差的量纲；零点附近用绝对误差或明确的特征尺度归一化，避免以趋近零的参考值做相对误差分母。解析场误差、积分误差、网格插值误差和显示偏差分别检查，方法见[分层验证](tutorial/04-slices-and-validation.md#validation-evidence)。

### 集成测试

- 多个种子共用同一追踪器；
- 正反分支合并时不重复种子点；
- 越界、弱场、奇点和闭环产生正确终止原因；
- 采样解析场再插值追踪，与直接解析追踪在网格细化时收敛一致。

### Web 契约测试

使用测试客户端覆盖：

- `GET /api/health` 返回成功和稳定状态字段；
- `GET /api/presets` 返回可用于场景请求的标识符，以及可编辑点源预设的严格最小中心距能力；
- `POST /api/scene` 的完整与最小合法请求；
- 非法预设、负密度、过大分辨率和畸形源被拒绝；
- `scalar.values`、`mask` 数量与 `nx * ny` 一致，且 masked 项恰为 JSON `null`、未遮罩项是未按色标裁剪的有限原值；
- 所有曲线点都在声明的坐标约定下可解释；
- 响应包含单位、`projection_note`、枚举 `seed_mode`、非空 `seed_description`，以及严格非负整数的双端终止、抑制与渲染统计；
- 电荷的正负向 job 合计恰好消耗总预算，只有已有同源对正向代表的反向线被抑制；
- 默认 Halbach 双轨和单磁偶极赤道线使用 `BOTH`，点序沿正场方向且双端原因分别可审计；
- 圆环非轴种子对应的公开 $\psi$ 值等间距，奇数预算保留唯一轴线 job；
- active 源中心距等于或小于能力下限、以及全零磁偶极场景都返回精确的 422 契约。

### 前端测试

无构建前端仍需要测试。至少覆盖：

- API 请求失败时显示错误，不保留“看似已更新”的旧状态；
- 标量、场线、箭头和源共用同一坐标变换；
- 对数尺度不会对零值或 mask 产生虚假热点；
- 探针显示未裁剪原值，科学详情显示场模型、播种枚举与说明、双端终止统计、抑制数和实际渲染数；
- 未知未来 `seed_mode` 与终止原因原样显示，旧自由文本 mode 缺少独立说明时也能降级展示；
- `density` 步长为 1，奇数预算可提交；默认 Halbach 的双轨不被八个 marker 错误抬高，自定义场景仍满足 active 播种源的最小预算；
- 数值编辑在源间距冲突时回滚，拖动吸附到合法边界；
- 拖动期间旧热图、色标和场线隐藏，只在松开后为最终位置发出一次请求；
- 热图纹素中心落在标量节点上，与探针读数的网格一致；
- 画布焦点环、色标和探针不被舞台裁切，色标不压住图面，探针不遮挡图旁的色标；桌面、投影仪、平板和手机视口的首屏都能看到完整图面，科学详情可以滚动到；
- 无法着色的格点画灰底斜线，只在斜线露出标记外时显示图例；色标超限尖角与播种信息行随场景状态出现，拖动时隐藏且不移动图面；
- 静态资源不引用外部 URL 或第三方品牌名，样式令牌满足文字 4.5:1、控件描边与焦点 3:1 的对比度下限；
- 改变显示图层不再次请求物理场景，也不改变图框几何；
- 斜率短线只从向量网格画、等长且与格点场方向一致，探针的方向角与分量读自同一格点；
- 光标预览束在浏览器里算（匀强场上 RK4 精确到舍入，线性旋转场上闭合且半径漂移可控），出现与消失都不发请求；点击把种子放进请求 `seeds`，响应里的手动统计与 `seed_index` 经校验后原样显示，拖动不算点击，清除后请求不再带种子；
- 滑块在松手（`change`）时提交一次，拖动中的 `input` 事件不发请求；
- 窗口缩放后坐标与指针探针仍一致。

截图测试只适合防止布局意外变化，不能替代数值和语义断言。

前端入口和纯函数使用浏览器原生 ES module，由 uv 管理的 Python Playwright 在 Chromium 中直接执行；仓库不使用 `package.json`、Node 包管理器或 bundler。首次运行或 Playwright 升级后安装匹配的浏览器：

## 添加新物理场

1. 先写定义、单位、坐标系和奇点集合。
2. 实现批量 `evaluate(points)`，保持前导维度。
3. 添加解析点值与对称性测试。
4. 添加旋转、缩放或远场标度等性质测试。
5. 将模型接入追踪器，验证切向残差。
6. 最后才添加预设与前端控件。

若模型只能在某个对称平面给出，应在类型或元数据中明确表达，不能把它包装成任意三维场。

## 添加新场景预设

预设负责组装已有模型，不应复制公式。每个预设至少声明：

- 稳定标识符和用户标题；
- 默认源与计算域；
- 标量量、单位和默认尺度；
- 播种策略及 `density` 的实际含义；
- 是真实二维场线还是投影；
- 安全的分辨率和源数量上限。

随后更新 `/api/presets` 契约测试和 [API 参考](api.md)。

## 性能与基准

先批量化，再考虑 JIT 或 GPU。性能改动必须保留数值结果并提供前后基准：

- 默认要求结果逐位不变：对改动前后的同一组场景，逐个追踪任务比较终止原因、右端函数调用次数和点数组，而不只比较最终图像；
- 单点快速路径只使用 IEEE 754 正确舍入的 `+ - * /` 与 `sqrt`、与批量路径共用的同一个 Python 表达式（例如 `radius**2`），以及与批量路径相同的 SciPy ufunc；分数次幂留在数组路径，因为 NumPy 可能以 SIMD 实现数组 `pow`，结果末位可能不同于标量 `pow`；
- Python 浮点除以零会抛出 `ZeroDivisionError`，NumPy 则返回 `inf` 或 `nan`，所以分母可能下溢为零或不是有限值时，单点路径回落到数组路径；
- 记忆化或缓存要保存自己的副本：自定义场可能复用输出数组，调用方也可能修改返回的响应；
- 会改变数值结果的优化（例如跨种子向量化）需单独评估误差，并更新相关基准测试；
- 分离场采样时间、播种时间、积分时间和 JSON 序列化时间；
- 记录点数、源数、种子数和容差；
- 避免一次构造 `N_points × N_sources × D` 的巨大临时数组，必要时按源或点分块；
- 计算可用 `float64`，向浏览器传输时经误差评估后才考虑 `float32`；
- 当前前端拖动点源时隐藏已失效的物理图层，只在停止后请求一次结果；未来若增加低分辨率预览，必须显式区分预览与最终场景。

### v0.3.3 基准 { #v033-benchmark }

下表是经 ASGI 应用端到端请求 `POST /api/scene`（`density=18`，`resolution=80`）的耗时，包含场采样、追踪和 JSON 序列化。v0.3.2 与 v0.3.3 在同一台 Windows 11、Python 3.13 机器上交替运行两轮，每轮 7 次，取两轮中位数的平均，四舍五入到 10 ms。

| 预设 | v0.3.2 | v0.3.3 |
|---|---:|---:|
| `electric_dipole` | 240 ms | 210 ms |
| `magnetic_dipole` | 480 ms | 430 ms |
| `halbach_array` | 230 ms | 200 ms |
| `current_loop` | 1480 ms | 360 ms |
| `uniform` | 230 ms | 190 ms |

紧接着以 `resolution=96` 请求同一场景时，v0.3.3 命中曲线缓存，各轮中位数在 6–31 ms 之间；v0.3.2 没有曲线缓存，耗时与首次请求相同。首次请求的提速来自三处：去掉单点求值时 NumPy 包装函数的开销、事件函数复用右端函数刚算过的场值，以及圆环一般区域的单点浮点路径。缓存命中后的剩余耗时是标量网格采样和序列化。首次请求两轮之间的差异约 5%；验收方在同一台机器上独立复测的首次请求降幅（圆环约 75%，其余约 10–20%）与此一致。

逐位不变的检查覆盖 64 个场景：五个预设各取 4 种预算和 3 种分辨率，另加不等强电荷、三电荷、旋转磁偶极和含零强度偶极的编辑后 Halbach 阵列。每个场景的完整响应 JSON，以及每个追踪任务的终止原因、右端函数调用次数和点数组，均与 v0.3.2 相同；同一预算的后两种分辨率走缓存命中，因此这也检查了命中后的响应。验收时另用 771 条对抗记录比较了核心接口：随机源布局、倾斜圆环加环面排除区的三维追踪，以及各种输入形状、整数与列表输入、NaN/inf、轴上与导线上的点，Windows 与 WSL Ubuntu 上均与 v0.3.2 逐位相同。这些是抽样验证，不是对所有输入和所有 NumPy 构建的证明；阈值、下溢和复用输出数组等已知边界由 `tests/test_loop_fields.py` 与 `tests/test_tracing.py` 的回归测试覆盖。磁偶极子与点电荷剩余的主要开销是分数次幂和 `einsum`，按上面的规则留在数组路径。

### Radau 界面事件的后续修复（2026-11-10）

排除区复审还发现一项原有界面问题：`UniformField((1, 0))` 从 `(0, 0)` 正向出发，域为 `(-1, -1)` 至 `(1, 1)`，登记圆心 `(0, 0)`、半径 `0.1` 的球形 `interface`，使用 `Radau` 与 `max_step=0.1`，会抛 `ValueError: f(a) and f(b) must have different signs`。在 `b51db6c` 与 `84c8c92` 都复现，且输入没有排除区。

根因直接由步进状态与插值输出对照确认：距离限步让首段结束于 `s=0.1`，Radau 已接受的横坐标恰为 `0.1`，但稠密输出在同一端点的重算值小 4 ulp，界面 `margin=-5.551115123125783e-17`。SciPy 用已接受状态触发事件，却用稠密输出括区求根，后者两端都为负。修复在 Radau 适配器的稠密输出上加入线性端点残差校正，并复制保存两端的已接受状态；三次曲线的次数不变，步内几何检查仍适用。

先运行再修复的回归共有 10 项：正反两个方向 × 自适应和等距输出，以及正反方向下排除入口在界面之前、同位、之后的 6 种情况，修复前全部因相同括区异常失败。修复后同时保留解析折线对照，检查折射点与已知出口位置，不能只以“不抛异常”为验收标准。

独立检查另覆盖 20 个解析控制：双向折射、表面出发、闭环与排除区的先后、球与环面的平移旋转缩放、浅穿与近失，结果均符合预期，弧长严格递增。直接对照原 SciPy Radau 的正逆时间圆周积分共 311 步，已接受时间与状态逐位相同，`nfev/njev/nlu` 相同；标量、重复乱序数组、空数组和旧插值对象在后续步进后的稳定性也通过。1000 个内部采样点的最大变化为 `2.22e-16`。
